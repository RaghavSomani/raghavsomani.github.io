# raghavsomani.github.io

Source for [Raghav Somani's personal website](https://raghavsomani.github.io/), including research projects, publications, technical notes, and a curriculum vitae.

## Local development

The site is built with Jekyll and the GitHub Pages dependency set.

The lockfile follows `github-pages` 232 with Jekyll 3.10.0, including its required `jekyll-relative-links` 0.6.1 pin. CI uses Ruby 3.3.

1. Install Ruby, Bundler, and Node.js 22.22+ on the 22.x line, or Node.js 24.8+.
2. Run `bundle install`.
3. Run `npm ci`.
4. Run `bundle exec jekyll serve --config _config.yml,_config.dev.yml`.
5. Open `http://localhost:4000`.

On this Windows workstation, run `serve-local.bat` to start the WSL-based development server with automatic rebuilding. Refresh the browser manually after edits; LiveReload is disabled because malformed client requests can stop the pinned preview server. Keep its terminal open while reviewing the site and press Ctrl+C when finished.

Run `npm run build` to build the site with math pre-rendering. Set `JEKYLL_ENV=production` for a production build. On Windows, `run.bat` sets that environment and runs the build, an internal-link check, and a concise Git status. The script deliberately does not stage, commit, or push changes.

Run `npm run preview` to view the built site at `http://localhost:4000/`, including pre-rendered math. This server resolves extensionless project and publication links to their generated HTML files. Rebuild the site after editing content to refresh this preview.

If the browser JavaScript sources are changed, rebuild `assets/js/main.min.js` with `npm run build:js` before committing.

The shared script uses native navigation, audio controls, and CSS scrolling and sticky positioning. Pages containing image links load `assets/js/image-viewer.min.js` separately, including the locally patched image viewer and its jQuery dependency. `npm run build:js` generates both bundles, and `npm run watch:js` rebuilds them as sources change.

After building the site, run `npm run check:html` for the same structural HTML checks used in CI.

For browser checks, install Chromium once with `npx playwright install chromium`, then run `npm run check:lightbox` and `npm run check:accessibility`. Set `CHROME_BIN` to use an existing Chrome or Chromium executable instead. Accessibility checks cover representative pages at desktop and mobile widths, open menus, the skip link, lightbox focus, and a mobile photo budget; third-party widgets are excluded from these local checks.

Travel photographs use committed JPEG/WebP variants generated by `npm run build:images`. Run it after changing originals under the three travel-photo folders. The generated `_data/responsive_images.json` supplies dimensions and responsive sources to the gallery, feature images, and hero; full-resolution originals remain available in the lightbox.

Icon fonts and sharing images are generated with `npm run build:icons`. Run this after adding icon classes to the source. The committed WOFF2 subsets include the icons used by the templates and content. Sharing images are sized for high-density screens.

Set `mathjax: true` in front matter for articles using inline TeX delimiters. Pages with Kramdown-generated math are also detected automatically, including archive excerpts. `npm run build` runs Jekyll followed by `scripts/prerender-math.mjs`, which renders equations into HTML and accessible MathML, preserving the original TeX as annotations. Fonts are copied into the generated site, and the browser receives the rendered equations. Math errors stop the build with the affected page's filename. The Jekyll development server uses browser-side MathJax to preview edits immediately.

GitHub Pages must use **GitHub Actions** as its publishing source under **Settings → Pages → Build and deployment**. The workflow builds and checks the site before uploading and deploying `_site` on pushes to `master` or manual runs. Pull requests run the build and checks.

Analytics tags are emitted only when `JEKYLL_ENV=production` and the configured provider is enabled; preview builds omit them.

## Content

- `_pages/` contains top-level pages.
- `_posts/` contains technical notes.
- `_projects/` contains project pages.
- `_publications/` contains publication pages and metadata.
- `_data/navigation.yml` controls the primary navigation.
- `_config.yml` contains site-wide identity, metadata, and collection settings.

Pull requests run a pinned Jekyll build, internal-link and structural HTML checks, lightbox regression checks, and browser accessibility checks through `.github/workflows/site-checks.yml`. These checks also verify pre-rendered equations, MathML, and icon subset loading.
